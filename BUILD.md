# Сборка прод-версии для тестировщиков

Цель: получить один файл-установщик, который товарищи просто скачивают и
ставят двойным кликом — без Node.js, без консоли, без `npm install`.

## 1. Соберите установщик (делаете вы, один раз на релиз)

```bash
cd lspd-mdt
npm install        # если ещё не делали
npm run dist
```

Это:
1. Соберёт renderer (`vite build` → папка `dist/`).
2. Упакует Electron-приложение через `electron-builder` в **папку
   `release/`** (не путать с `dist/` — там лежит только веб-бандл).

На Windows появится:
```
release/LSPD MDT Assistant Setup 0.1.0.exe
```
Это и есть файл, который вы отдаёте тестировщикам. Один `.exe`, ничего
больше пересылать не нужно.

> Собирать под Windows лучше на Windows (или через WSL/CI) —
> кросс-сборка `.exe` с Linux/macOS возможна, но менее надёжна для
> Electron-приложений с нативными зависимостями.

## 2. Что видит тестировщик

1. Скачивает `LSPD MDT Assistant Setup 0.1.0.exe`.
2. Двойной клик → обычный мастер установки Windows (Next → Next → Install).
3. Windows SmartScreen скорее всего покажет предупреждение
   **"Windows защитила ваш компьютер"** — это нормально для неподписанных
   приложений (см. раздел ниже про подпись). Нажать **"Подробнее" →
   "Выполнить в любом случае"**.
4. Приложение ставится и запускается как обычная программа — ярлык на
   рабочем столе/в меню Пуск, никакой консоли.

## 3. Про первый запуск у тестировщика

Раньше здесь стоял выбор из трёх вариантов, потому что Discord-секреты
(Client ID/Secret, Bot Token, каналы, роли) жили локально на каждой
машине. После перехода на backend это уже не так: клиенту нужен только
**адрес backend'а**, а он либо зашит в сборку (см. ниже, вариант В —
теперь единственный практический), либо тестировщик один раз вводит
его сам в Настройках (это просто URL, не секрет — не страшно продиктовать
голосом или написать в чат).

**Вариант В — зашить адрес backend'а в сборку один раз (уже так и есть).**

С переходом на backend (см. `lspd-backend`) вариант В стал единственным
осмысленным способом — Discord-токены больше не хранятся на клиенте
вообще, зашивать в сборку нечего, кроме адреса сервера:

1. Скопируйте `electron/seed-config.example.json` → `electron/seed-config.json`.
2. Укажите там `backendUrl` — адрес вашего backend'а (например
   `"http://72.56.70.40"`, позже — ваш домен по HTTPS).
3. `npm run dist` — файл автоматически зашивается в сборку.
4. Тестировщик ставит `.exe` и сразу видит экран **«Войти через
   Discord»** — без PIN, без единого поля для ручного ввода.

Как это работает: при первом запуске на чистой машине приложение
проверяет, есть ли уже сохранённый адрес backend'а; если нет —
подставляет значение из `seed-config.json`. Дальше живёт в локальном
`electron-store` тестировщика, и seed-файл больше не трогается.

`electron/seed-config.json` уже в `.gitignore`. Никаких секретов в нём
больше нет — это просто адрес сервера, не токен, можно спокойно
пересылать код кому угодно даже с этим файлом.

**Про безопасность — стало проще.** Раз backend теперь единственный,
кто держит Bot Token и Client Secret, у тестировщиков на дисках вообще
не оказывается ничего чувствительного. Единственное, что стоит держать
в уме: сам backend должен быть доступен только вам (`SUPER_ADMIN_SECRET`
для `/api/admin/*` — не давайте его никому), и сервер имеет смысл
защищать как обычный продовый сервер (SSH только по ключу, файрвол,
регулярные обновления — это всё уже сделано при разворачивании).

## 4. Про цифровую подпись (SmartScreen-предупреждение)

Предупреждение Windows появляется, потому что `.exe` не подписан
сертификатом издателя. Для закрытого тестирования среди своих это
абсолютно нормально и безопасно — сборка была собрана у вас на глазах,
никакого стороннего кода. Убрать предупреждение можно только купив код-
signing сертификат (стоит денег, имеет смысл только для публичного
релиза) — для теста внутри сообщества не нужно.

## 5. Обновление без переустановки

Два независимых механизма — можно использовать любой или оба:

**А) Просто пересобрать и разослать новый `.exe` (уже работает, ничего настраивать не надо).**
NSIS-установщик, который собирает `npm run dist`, — режим `oneClick`.
Если тестировщик запустит новый `Setup.exe` поверх уже установленной
версии, файлы обновятся на месте, **без деинсталляции**: не нужно
сначала удалять старую версию. Настройки в `electron-store` (Discord-
конфиг, хоткеи, позиции окон) при этом сохраняются — они лежат отдельно
от файлов программы.

**Б) Проверка обновлений прямо в приложении (кнопка "Проверить
обновления" на экране аккаунта).** Работает через `electron-updater`, но
требует, чтобы вы **публиковали релизы**, а не просто держали `.exe` у
себя на диске:

1. Заведите GitHub-репозиторий (можно приватный, но тогда нужен токен
   с доступом даже для скачивания релиза — проще сделать публичным,
   если утечка кода вас не смущает).
2. В `package.json → build.publish` замените `"ВАШ_GITHUB_ЛОГИН"` на
   свой логин/организацию.
3. Соберите и сразу опубликуйте релиз одной командой:
   ```bash
   $env:GH_TOKEN="ваш_github_personal_access_token"   # PowerShell
   npm run dist -- --publish always
   ```
   Токен — Settings → Developer settings → Personal access tokens,
   права достаточно `repo` (для приватного) или `public_repo`.
4. `electron-builder` сам создаст GitHub Release с нужными файлами
   (`.exe`, `latest.yml` — по нему `electron-updater` понимает, что
   вышла новая версия).
5. У тестировщиков, которые уже поставили **предыдущую** версию (с этим
   же `publish`-конфигом внутри), кнопка "Проверить обновления" найдёт
   новый релиз, предложит скачать и после скачивания — перезапустить и
   установить. Самую первую версию всё равно ставят через `.exe` руками.

> ⚠️ Я не смог протестировать этот механизм живьём — в песочнице нет
> доступа в интернет и GitHub-аккаунта. Код написан по документации
> `electron-updater`, но первую проверку всё равно лучше сделать на
> двух своих машинах перед тем, как полагаться на неё с тестировщиками.

Если варианта с GitHub нет (например, всё приватно и без облака) —
`electron-updater` поддерживает и `"provider": "generic"` с обычным URL
на статический файл-сервер (свой хостинг/S3/что угодно, что отдаёт
файлы по HTTP) — конфигурация в `package.json` меняется на:
```json
"publish": { "provider": "generic", "url": "https://ваш-сервер/releases/" }
```
и обновления кладутся туда вручную после каждой сборки.

## 6. Если сборка на Windows падает с ошибкой symlink / code signing

Частый случай: `npm run dist` падает с многократным
`Cannot create symbolic link` при распаковке `winCodeSign` (в кэше
`%LocalAppData%\electron-builder\Cache\winCodeSign`). Это не баг проекта —
`electron-builder` тянет пакет с mac-инструментами (там есть symlink'и)
даже при сборке только под Windows, а Windows по умолчанию запрещает
создавать symlink без спецправа.

Исправление:
1. Включите **Режим разработчика**: `ms-settings:developers` → тумблер
   Developer Mode. (Альтернатива, если это недоступно на управляемом ПК:
   запустите терминал **от имени администратора** и собирайте из него —
   права администратора дают то же самое право на symlink.)
2. Удалите битый кэш: `%LocalAppData%\electron-builder\Cache\winCodeSign`
   (после неудачных попыток там остаются недораспакованные архивы).
3. Повторите `npm run dist`.
