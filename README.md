# LSPD MDT Assistant — клиент (Electron)

Electron-приложение для полицейского RP-департамента. Работает **поверх игры**
как обычное десктоп-окно (без чтения памяти процесса игры и без вмешательства
в сам GTA5/FiveM), с глобальными хоткеями F7–F11.

**Архитектура изменилась с версии 2.0 Alpha.** Discord-токены, форум-каналы
и маппинг ролей больше не хранятся на этом клиенте — этим занимается
отдельный backend-сервис (`lspd-backend`, разворачивается на VPS). Этот
Electron-проект теперь — тонкий клиент: он говорит с backend по HTTP и
знает только его адрес. Все инструкции по настройке Discord (бот, каналы,
маппинг ролей/отделов/должностей) — в README **`lspd-backend`**, не здесь.

## Архитектура окон (важно)

Приложение — это НЕ одно окно с разделами, а несколько независимых
плавающих прозрачных окон Electron поверх игры, как на ваших макетах:

| Окно | Хоткей | Расположение по умолчанию |
|---|---|---|
| **Police Assistant** (quickmenu) | F7 | верх-право |
| **Радио** (реальные голосовые каналы) | F8 | верх-лево |
| **MDT** (Дела/Персоны/Транспорт/Ордера/Улики/BOLO/Сотрудники) | F9 | низ-лево |
| **Памятка** (Кодекс) | F10 | центр |
| **Discord** (лог) | F11 | низ-право |
| **Ctrl+K** — показать/скрыть сразу все открытые панели | — | — |

Отдельно есть **окно логина/настройки** (authWindow) — обычное,
непрозрачное, с рамкой своей вёрстки. Оно открывается при старте
приложения, а после успешного входа через Discord автоматически
прячется, уступая место панели Police Assistant. Чтобы вернуться к
настройкам/выходу из аккаунта — используйте кнопку "⚙ Настройки" в
панели или системный трей.

Каждая панель = отдельный `BrowserWindow` (`frame: false, transparent:
true, alwaysOnTop: true, skipTaskbar: true`), рендерящий один и тот же
`index.html`, но с разным `#hash` в URL (например `#/mdt`, `#/codex`) —
так `src/App.tsx` понимает, какой компонент показать именно в этом
окне. Файл `electron/windows.js` управляет позициями/размерами и
показом/скрытием.

**Технический нюанс**, о котором стоит знать: раз это разные процессы
рендерера, они не делят между собой JS-состояние (zustand-стор) —
каждая панель сама запрашивает сессию офицера через
`useOfficer()` (см. `src/state/useOfficer.ts`).

## Что уже реализовано

- 6 плавающих окон-панелей + окно логина/настройки (см. таблицу выше).
- Глобальные хоткеи F7–F11 + K — переключают видимость соответствующих окон.
- Стиль карточек/цвета/отступы подогнаны под присланные макеты
  (тёмно-синяя палитра, скруглённые карточки, теги-бейджи статусов).
- Экран первичной настройки — теперь просит только **адрес backend'а**
  (например `http://72.56.70.40`), закрыт PIN-ом администратора
  (дефолтный PIN: `1234`, смените сразу после первого входа).
- Настоящий Discord OAuth2-флоу логина через системный браузер — но
  теперь в два прыжка: браузер → backend → Discord → backend → обратно
  локальному клиенту с уже готовым JWT-токеном. Проверка членства,
  звания/отдела/должности — всё это делает backend, клиент просто
  получает готовый профиль офицера через `/api/auth/me`.
- MDT-вкладки **Дела**, **Персоны**, **BOLO**, **Транспорт**, **Ордера** —
  читают/создают/редактируют треды в форум-каналах Discord по шаблону
  "Ключ: значение". Транспорт: гос.номер, модель, цвет, владелец, статус
  розыска. Ордера: номер, тип, подозреваемый, основание, кто выдал, статус.
  Персоны: ФИО, дата рождения, телефон, адрес, лицензии, судимости,
  заметки, фото (вложения) и список связанных дел.
- **Связь «дело ↔ гражданин»** строится по точному совпадению поля
  «Подозреваемый» в деле с ФИО в картотеке. Это простой механизм без
  отдельных идентификаторов: опечатка или другое написание имени разорвёт
  связь. Если понадобится надёжнее — можно перейти на хранение threadId
  гражданина в поле дела.
- MDT-вкладка **Сотрудники** — реальный личный состав фракции (список и
  звания приходят с backend), группируются по званию, показывают значок,
  отдел, должность и текущий 10-статус, плюс статистику «создано/закрыто»
  по делам (тоже считает backend).
- **Статусы 10-кодов** (10-8 На смене / 10-6 Занят / 10-7 Не на смене) —
  кнопки в панели Police Assistant. Статус публикуется ботом в канал
  статусов (или логов, если отдельный не задан) строкой вида
  `📻 **ник** (значок) — 10-8 · На смене`; вкладка Сотрудники читает
  последние 100 сообщений этого канала и берёт свежую запись по каждому.
- **Памятка** — теперь тоже через форум-канал Discord (ID канала
  настраивается на backend'е): статьи заполняются прямо из приложения и
  хранятся как треды на сервере, как Дела/Граждане/BOLO. Если канал не
  настроен — показываются демо-статьи из `electron/localData.js` с подсказкой.
- **Рация (F8)** — показывает голосовые каналы сервера и кто в них сидит
  (с индикаторами mute/deaf), обновляется каждые 10 секунд. Если у вас
  есть право **Move Members**, рядом с участником появляется кнопка
  перевода в другой канал. Право проверяется в main-процессе, а не только
  в интерфейсе. Требует интента **Server Voice States** (включается там же,
  где Server Members Intent) — голос бот не передаёт и передавать не может.
- **Памятка** — разделы (Кодекс, Процедуры, Радио/Команды, Инструменты,
  Полезная информация). В любой раздел можно добавлять свои записи, а не
  только статьи кодекса: номер статьи необязателен. Внутри раздела —
  категории, которые создаются простым вводом названия и переименовываются
  карандашом. Записи можно создавать, редактировать и удалять.
- **Размер окон** — все панели растягиваются за края; размер и позиция
  сохраняются между запусками. В узком окне подписи вкладок скрываются,
  остаются только значки, а двухколоночные экраны складываются в одну
  колонку. Сброс раскладки — кнопка в Настройках.
- **Дашборд «LSPD Assistant»** — отдельная крупная панель (кнопка «Главная»
  в Police Assistant): статистика по делам/BOLO/базе, активное дело,
  быстрые ссылки на все остальные панели, карточка Discord, сводка по базе.
  Открывается своим окном и не закрывает Police Assistant.
- **Настройки доступны прямо во время работы приложения**, не только на
  первом запуске: отдельная панель «Настройки» (шестерёнка в дашборде).
  Доступ к ней даёт либо роль-администратор из списка `adminRoleIds`
  (задаётся в самих Настройках), либо PIN — как и раньше.
- **Роли доступа**: `allowedRoleIds` — если список не пуст, входить в
  приложение могут только участники с одной из этих ролей (иначе — вход
  всем участникам сервера, как раньше). `adminRoleIds` — у кого есть
  такая роль, видит Настройки без PIN.
- **Фирменные элементы**: герб LSPD (собственная простая эмблема, не
  копия реальной печати) слева в шапке каждой панели, приглушённый флаг
  США справа. Компоненты — `src/components/LSPDBadge.tsx` и
  `USFlagIcon.tsx`, замените на свою графику при желании.
- **Переназначаемые хоткеи** — в Настройках («Хоткеи») можно поменять
  клавишу для каждой панели, добавить новую привязку или удалить старую.
  Применяется сразу, без перезапуска приложения.
- **Прозрачность окон** — в Настройках («Прозрачность окон») можно
  включить автозатухание: панель становится прозрачнее, когда вы кликаете
  обратно в игру (окно теряет фокус), и возвращается к обычному виду при
  взаимодействии с самой панелью. Регулируются оба уровня прозрачности.
- **Клик сквозь панели ("не мешать мыши в игре")** — по умолчанию панели
  не перехватывают клики и наведение мыши: курсор игры ведёт себя так,
  будто программы нет (иначе Windows показывает системный курсор, как
  только он геометрически пролетает над окном во время вращения камеры,
  даже без клика). Хоткей **Insert** переключает "режим взаимодействия" —
  тогда можно кликать по кнопкам; в этом режиме на панели появляется
  значок замка 🔒. Реализовано через `setIgnoreMouseEvents` — штатный
  Electron-приём для HUD-оверлеев поверх игр.
- **Настройки разделены на два уровня.** «Настройки» (шестерёнка в
  дашборде, за PIN/ролью-админом) — теперь только адрес backend'а и смена
  PIN; всё остальное (каналы, маппинг ролей, права) настраивается на
  самом backend'е. «Мои настройки» (доступны любому вошедшему, без PIN) —
  хоткеи, прозрачность окон, сброс раскладки. Доступ — кнопка «МОИ
  НАСТРОЙКИ» в Police Assistant или пункт в сайдбаре дашборда.
- **Сообщения бота — оформленные embed'ы**, а не голый текст: шапка
  «LSPD | Broadcast Bot» с аватаркой бота, поля Отправитель/Канал/Тип/
  Время, текст сообщения, подпись «LSPD | Los Santos Police Department».
  Применено к созданию/закрытию дел, BOLO, ордерам, статусам офицера.
  Чтобы в шапке был герб LSPD — выставьте его аватаркой боту в Discord
  Developer Portal, иконка подтянется автоматически.
- **Трансляция из Биндера** — текстовое поле + кнопка «Транслировать в
  Discord»: уходит тем же оформленным embed'ом в канал логов с типом
  «Трансляция (биндер)» и вашим ником/ID отправителя.
- **Иконка приложения и полноценный выход** — у программы теперь есть
  свой значок (`build/icon.png` / `icon.ico`, простая эмблема LSPD,
  сгенерирована для прототипа). Трей-иконка всегда создаётся и содержит
  пункт «Выход». Закрыть программу можно тремя способами на случай, если
  трей потерялся в скрытых значках Windows: хоткей **Ctrl+Alt+Q** (работает
  всегда, независимо от того, что открыто), кнопка ⏻ на экране аккаунта,
  кнопка ⏻ в шапке дашборда «Главная».
- **Обновление без переустановки** — два способа, подробности в
  [BUILD.md](./BUILD.md): (1) новый `.exe`-установщик и так обновляет
  файлы поверх старой версии, без удаления; (2) кнопка «Проверить
  обновления» на экране аккаунта через `electron-updater` — требует
  настроенной публикации релизов (GitHub Releases или свой сервер),
  не протестирована живьём (нет интернета в песочнице).
- Две цветовые темы плавающих панелей: бордово-винная — Police
  Assistant и MDT (по референсам), тёмно-синяя — Памятка/Биндер/Радио/
  Discord/окно логина. Переключается пропом `theme` в `FloatingPanel`.

### Известное ограничение прозрачных окон на Windows
`box-shadow` у плавающих карточек на некоторых связках Windows +
видеодрайвер может отрисовываться грубее, чем в браузере (артефакты по
краям прозрачной области). Если увидите это — можно временно
поставить `hasShadow: true` и убрать CSS `box-shadow`, либо принять
как визуальный компромисс прототипа.

## Что нужно доделать вам / не реализовано

- **Вложения-скриншоты** — не перенесены с локальной версии на backend
  (нужен `multipart/form-data` пайплайн). Кнопка в интерфейсе сейчас
  честно отвечает «функция недоступна» вместо того, чтобы притворяться.
- **Rate-limit форум-каналов Discord** — backend делает прямой запрос к
  Discord API на каждый `GET`, без кэша. При росте нагрузки понадобится
  локальный кэш на стороне backend (обновление раз в 10–15 сек в фоне).
- **UI управления фракциями/маппингом ролей** — панель «Фракции и роли» в
  клиенте (гейт по `SUPER_ADMIN_SECRET`): создание фракций, 4 таблицы
  маппинга (Звания/Отделы/Должности/Академия) с добавлением/редактированием/
  удалением строк. Заполнены пока не все звания/отделы/должности с ваших
  плакатов — структура готова, ввод данных для LSPD (кроме CHIEF) и
  остальных 8 фракций альянса ещё предстоит сделать через эту панель.

## MDT 2.0 Alpha — что добавилось

- **Ролевая иерархия прав.** Настраивается на backend'е числовым порогом
  звания (`manageThreshold` фракции): ниже порога — только создание
  записей, на пороге и выше — редактирование/закрытие/удаление.
  Применено к Делам, Ордерам, Транспорту, Гражданам, BOLO, Памятке.
- **Улики** — новый модуль MDT (форум-канал `evidenceChannelId`): тип,
  привязка к номеру дела, кто изъял, местонахождение, статус (На хранении /
  Передано в суд / Возвращено / Уничтожено). В карточке дела появился блок
  «Улики по делу» — связь строится по точному совпадению номера дела.
- **Статистика по офицеру.** Закрытие дела теперь пишет, кто и когда его
  закрыл (поля «Изменил статус» / «Дата изменения»). Вкладка Сотрудники
  показывает у каждого «N создано / M закрыто»; в дашборде — личная
  карточка «Моя статистика».
- **Пресеты раскладки по роли.** На backend'е у каждого звания —
  `defaultPanels`: какие окна открываются автоматически при входе с этим
  званием (патрульному — Police Assistant, диспетчеру — Радио+Discord и
  т.д.). Кнопка «Раскладка по роли» в дашборде применяет пресет вручную
  в любой момент.
- **Живая лента в Discord-панели** — вместо статичного текста теперь
  реальные последние сообщения канала логов, автообновление каждые 15 сек.
- **Прозрачность для мыши** и **переназначаемые хоткеи** — см. отдельные
  пункты выше.

## Установка и запуск (у вас, с интернетом)

```bash
cd lspd-mdt
npm install
npm run dev
```

Это одновременно поднимет Vite (рендерер) и Electron (`concurrently`).
Если `npm run dev` не поднимает Electron — убедитесь, что Vite успел
стартовать на `http://localhost:5173` (см. `wait-on` в скрипте).

Сборка установщика:

```bash
npm run dist
```

## Настройка (для админа фракции)

Discord-бот, форум-каналы, маппинг званий/отделов/должностей — всё это
настраивается **на backend'е**, не в этом клиенте. Полная инструкция —
README проекта `lspd-backend` (создание Discord Application, приглашение
бота на серверы фракций, форум-каналы, `/api/admin/*` для маппинга ролей).

### Первый вход в клиент
1. Запустите приложение — увидите экран настройки, введите PIN `1234`
   (или тот, что уже сменили).
2. Укажите **адрес backend'а** (например `http://72.56.70.40`, позже —
   ваш домен по HTTPS) → Сохранить.
3. Обязательно смените PIN администратора там же.
4. Перейдите на экран логина → «Войти через Discord» → откроется ваш
   системный браузер на странице backend'а, который перекинет на
   официальную страницу Discord → подтвердите доступ → вкладку можно
   закрыть и вернуться в приложение — оно уже подтянуло ваш профиль
   (звание/отдел/должность/права) от backend'а.

   Авторизация намеренно открывается в системном браузере, а не во
   встроенном окне Electron: встроенный webview с полем ввода пароля
   Discord неотличим от фишинга, и Discord это не рекомендует.

Если у тестировщика уже зашит адрес backend'а в сборку (см. BUILD.md,
раздел про `seed-config.json`) — шаги 1–2 он не увидит вообще, сразу
попадёт на экран логина.

## Структура проекта

```
electron/         # main-процесс Electron (Node.js): окна, хоткеи, IPC,
                   # HTTP-клиент к backend'у (backendClient.js), OAuth-флоу
                   # (discordAuth.js), локальное хранилище настроек (только
                   # адрес backend'а, хоткеи, прозрачность — никаких секретов)
src/               # renderer (React + TypeScript, собирается Vite)
  screens/         # экраны 1:1 с вашими макетами
  components/      # общие UI-элементы
  state/           # zustand-стор (сессия офицера, активная панель)
  api/             # типизированная обёртка над window.electronAPI
```

## Безопасность

Никаких Discord-секретов на этом клиенте больше нет — ни Bot Token, ни
Client Secret, ни Client ID. Единственное, что хранится локально
(`electron-store`) — адрес backend'а, JWT-сессия текущего входа, личные
предпочтения (хоткеи, прозрачность). Замените `encryptionKey` в
`electron/store.js` на свой длинный секрет перед реальным использованием
— сейчас там placeholder-значение (не критично, раз секретов внутри и
так не осталось, но лучше не оставлять как есть).

Всё, что раньше было проблемой безопасности этого README (Bot Token на
дисках тестировщиков), теперь решено архитектурно — см. `lspd-backend`.
